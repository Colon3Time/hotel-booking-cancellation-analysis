# Hotel Booking Cancellation Analysis

วิเคราะห์การยกเลิกการจองห้องพักของโรงแรม 2 แห่ง (City Hotel + Resort Hotel) เพื่อหาว่าการยกเลิกทำให้รายได้หายเท่าไหร่ และควรรับมือกับกลุ่มไหนอย่างไร

## โจทย์ธุรกิจ

**ผู้ใช้ผลงาน:** Revenue Manager ของกลุ่มโรงแรม

**ปัญหา:** การจองจำนวนมากถูกยกเลิก ห้องที่กันไว้ขายต่อไม่ทัน ทำให้ห้องว่างและรายได้หาย

**การตัดสินใจที่ต้องการ:**
- กลุ่มลูกค้าหรือช่องทางไหนควรเก็บมัดจำ
- ควรรับจองเกินจำนวนห้อง (overbook) มากแค่ไหนในแต่ละช่วงฤดูกาล
- ช่องทางจองไหนควรลดการพึ่งพา

**คำถามธุรกิจ:**
1. อัตรายกเลิกของแต่ละโรงแรม ช่องทางจอง (`distribution_channel`) และกลุ่มลูกค้า (`market_segment`) เป็นเท่าไหร่ — ต้องรายงาน **จำนวนการจองของแต่ละกลุ่มคู่กับอัตราเสมอ** เพราะกลุ่มที่อัตราสูงแต่มีการจองไม่กี่ร้อยรายการไม่คุ้มที่จะลงมือแก้
2. ยิ่งจองล่วงหน้านาน (`lead_time`) ยิ่งเสี่ยงยกเลิกไหม และเริ่มเสี่ยงที่กี่วัน
3. ประเภทมัดจำ (`deposit_type`) สัมพันธ์กับการยกเลิกอย่างไร
4. รายได้ที่หายจากการยกเลิกต่อเดือนประมาณเท่าไหร่ (ราคาห้องเฉลี่ยต่อคืน × จำนวนคืน)
5. เดือนหรือฤดูกาลไหนมีการยกเลิกและรายได้หายมากที่สุด
6. ลูกค้าเก่า (`is_repeated_guest`) ยกเลิกน้อยกว่าลูกค้าใหม่ไหม
7. **ปัจจัยอะไรสัมพันธ์กับการยกเลิกมากที่สุด** — ข้อ 1–6 ตอบว่า "ยกเลิกเท่าไหร่" ข้อนี้ตอบว่า "ทำไมถึงยกเลิก" เพื่อให้เสนอได้ว่าควรแก้ที่จุดไหน ไม่ใช่แค่ตั้งรับ สมมติฐานที่จะทดสอบ:
   - `adults` / `children` / `babies` — กลุ่มใหญ่หรือครอบครัวยกเลิกต่างจากผู้เข้าพักคนเดียวไหม
   - `meal` — การจองที่ไม่มีแพ็กเกจอาหาร (SC/Undefined) ยกเลิกมากกว่าไหม
   - `previous_cancellations` — ลูกค้าที่เคยยกเลิกมาก่อนมีแนวโน้มยกเลิกซ้ำไหม
   - `total_of_special_requests` — ยิ่งขอเยอะยิ่งตั้งใจมาจริง ยกเลิกน้อยลงไหม
   - `booking_changes` — แก้ไขการจองบ่อยสัมพันธ์กับการยกเลิกไหม
   - `customer_type` — Transient / Group / Contract ต่างกันแค่ไหน

   ทุกข้อต้องเทียบกับอัตรายกเลิกรวมจากข้อ 1 เพื่อดูว่าต่างจากค่าเฉลี่ยจริงหรือไม่

**KPI:** Cancellation Rate · Lost Revenue · ADR (Average Daily Rate) · Average Lead Time · Repeat Guest Rate

## Dataset

- **Kaggle:** [Hotel booking demand](https://www.kaggle.com/datasets/jessemostipak/hotel-booking-demand)
- **ต้นฉบับ:** Antonio, N., de Almeida, A., & Nunes, L. (2019). *Hotel booking demand datasets*. Data in Brief, 22. https://doi.org/10.1016/j.dib.2018.11.126
- **ที่มาของข้อมูล:** ข้อมูลการจองจริงจากโรงแรม 2 แห่งในโปรตุเกส ปกปิดข้อมูลระบุตัวตนแล้ว (ไม่ใช่ข้อมูลสมมติ)
- **ขนาด:** 119,390 แถว × 32 คอลัมน์ (City Hotel 79,330 · Resort Hotel 40,060)
- **ช่วงวันเข้าพัก:** ก.ค. 2015 – ส.ค. 2017

### วิธีโหลดข้อมูล

ไฟล์ข้อมูลไม่ได้เก็บใน git (ดู `.gitignore`) ให้โหลดมาวางที่ `data/hotels.csv`:

```bash
curl -L https://raw.githubusercontent.com/rfordatascience/tidytuesday/master/data/2020/2020-02-11/hotels.csv -o data/hotels.csv
```

ไฟล์นี้เป็นชุดเดียวกับบน Kaggle (จำนวนแถวและคอลัมน์ตรงกัน) แต่โหลดได้โดยไม่ต้องล็อกอิน

### Data Dictionary

| คอลัมน์ | ความหมาย |
|---|---|
| `hotel` | ประเภทโรงแรม: City Hotel / Resort Hotel |
| `is_canceled` | ยกเลิกหรือไม่ (1 = ยกเลิก, 0 = ไม่ยกเลิก) |
| `lead_time` | จำนวนวันระหว่างวันที่จองกับวันเข้าพัก |
| `arrival_date_year` | ปีที่เข้าพัก |
| `arrival_date_month` | เดือนที่เข้าพัก |
| `arrival_date_week_number` | สัปดาห์ที่เข้าพัก (ลำดับสัปดาห์ของปี) |
| `arrival_date_day_of_month` | วันที่ของเดือนที่เข้าพัก |
| `stays_in_weekend_nights` | จำนวนคืนวันเสาร์-อาทิตย์ที่พักหรือจองไว้ |
| `stays_in_week_nights` | จำนวนคืนวันจันทร์-ศุกร์ที่พักหรือจองไว้ |
| `adults` | จำนวนผู้ใหญ่ |
| `children` | จำนวนเด็ก |
| `babies` | จำนวนทารก |
| `meal` | แพ็กเกจอาหาร: BB = อาหารเช้า, HB = 2 มื้อ, FB = 3 มื้อ, SC/Undefined = ไม่มีแพ็กเกจอาหาร |
| `country` | ประเทศของลูกค้า (รหัส ISO 3 ตัวอักษร) |
| `market_segment` | กลุ่มตลาด (TA = บริษัทนำเที่ยว, TO = ผู้จัดทัวร์) |
| `distribution_channel` | ช่องทางการจอง |
| `is_repeated_guest` | เคยเข้าพักมาก่อนหรือไม่ (1 = ลูกค้าเก่า) |
| `previous_cancellations` | จำนวนการจองที่ลูกค้าเคยยกเลิกก่อนการจองนี้ |
| `previous_bookings_not_canceled` | จำนวนการจองที่ลูกค้าเคยจองแล้วไม่ยกเลิก |
| `reserved_room_type` | ประเภทห้องที่จอง (รหัส ปกปิดชื่อจริง) |
| `assigned_room_type` | ประเภทห้องที่ได้รับจริง (อาจไม่ตรงกับที่จอง) |
| `booking_changes` | จำนวนครั้งที่แก้ไขการจองก่อนเข้าพักหรือยกเลิก |
| `deposit_type` | ประเภทมัดจำ: No Deposit / Non Refund (จ่ายเต็มจำนวน คืนเงินไม่ได้) / Refundable |
| `agent` | รหัสบริษัทนำเที่ยวที่ทำการจอง |
| `company` | รหัสบริษัทหรือหน่วยงานที่รับผิดชอบค่าใช้จ่าย |
| `days_in_waiting_list` | จำนวนวันที่อยู่ในรายการรอก่อนได้รับการยืนยัน |
| `customer_type` | ประเภทลูกค้า: Contract / Group / Transient / Transient-Party |
| `adr` | ราคาห้องเฉลี่ยต่อคืน (Average Daily Rate) |
| `required_car_parking_spaces` | จำนวนที่จอดรถที่ขอ |
| `total_of_special_requests` | จำนวนคำขอพิเศษ |
| `reservation_status` | สถานะสุดท้าย: Canceled / Check-Out / No-Show |
| `reservation_status_date` | วันที่สถานะล่าสุดถูกบันทึก |

### ข้อควรระวัง

- **`reservation_status` บอกผลการยกเลิกโดยตรง** (Canceled/No-Show = ยกเลิก, Check-Out = ไม่ยกเลิก) ห้ามใช้เป็นตัวอธิบายว่าทำไมถึงยกเลิก เพราะจะเป็น data leakage
- **`adr` มีค่าผิดปกติ** (ติดลบ, เท่ากับ 0, สูงผิดปกติ) ต้องตรวจก่อนคำนวณรายได้
- **ไม่มีรหัสการจอง** แถวที่ค่าเหมือนกันทุกคอลัมน์อาจเป็นการจองคนละรายการที่บังเอิญเหมือนกัน ต้องตัดสินใจก่อนลบแถวซ้ำ
- **`booking_changes` ตีความยาก (สำคัญกับข้อ 7)** การจองที่ยกเลิกเร็วมีเวลาแก้ไขน้อยกว่าตั้งแต่แรกอยู่แล้ว ถ้าพบว่า "แก้ไขน้อย = ยกเลิกมาก" อาจเป็นเพราะเวลาที่มี ไม่ใช่เพราะพฤติกรรมลูกค้า
